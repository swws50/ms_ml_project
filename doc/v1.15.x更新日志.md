# v1.15.x 更新日志

## 背景

预处理流程与业界代谢组学 SOP 存在三类差距：

1. **流程顺序错误**：归一化在阶段1（单文件级别），特征选择在阶段2，顺序与标准 SOP 相反，导致特征选择建立在未归一化的数据上
2. **特征筛选缺乏规范**：`ml_score = fold_change × coverage` 排序后硬截前50，无统计检验支撑
3. **缺失关键处理步骤**：缺失值直接填0、无 log 变换、无 Pareto scaling，数据分布假设错误

v1.15.x 目标：按标准 SOP 重组三阶段流程，补齐缺失步骤。

---

## 标准 SOP 顺序与当前实现对照

标准代谢组学 SOP 的阶段3后处理顺序为：

```
Peak alignment → Occurrence rate filtering → Imputation → Normalization → Log transformation → Scaling
```

各步骤顺序依据：

- **填补先于归一化**：归一化计算（sum/max/median）需要特征矩阵完整，有 NaN/0 会导致校正因子不准确
- **归一化先于 log**：归一化消除样本间系统性偏差（进样量差异），log 压缩异方差；若先 log 再归一化，log 已压缩数值范围，归一化效果被削弱
- **筛选先于 Pareto**：Pareto 后数值无量纲，fold change 失去生物学意义

| SOP 步骤         | 标准顺序 | 当前实现（v1.15.2）         | 状态          |
| -------------- | ---- | --------------------- | ----------- |
| 峰对齐            | 1    | 阶段2：0.2 Da 分组         | ✓           |
| 出现率过滤          | 2    | 阶段2：全样本缺失率 > 50%      | ✓           |
| 缺失值填补          | 3    | 未实现，缺失值保留为 0          | ✗           |
| 归一化            | 4    | 阶段3：矩阵构建时逐样本除以 TIC 因子 | 顺序错误（在填补之前） |
| Log 变换         | 5    | 未实现                   | ✗           |
| Pareto scaling | 6    | 未实现                   | ✗           |

> **v1.15.1 遗留问题**：将归一化从阶段1移到阶段3是正确方向，但在 `_build_unified_matrix` 中仍逐样本即时应用归一化（此时矩阵含大量 0），违反"填补先于归一化"原则。归一化因子来自阶段1的全峰 TIC（不依赖特征矩阵），因此 0 值归一化后仍是 0，实际数值无误，但架构顺序与 SOP 不符。v1.15.3 一并修正。

## 四阶段新职责划分

```
阶段1：峰拾取 + 收集归一化统计量（不应用归一化）
  ↓
阶段2：0.2 Da 分组对齐 → 产出完整共识峰备选池（不过滤）
  ↓
阶段3：全样本缺失率 > 50% 过滤（未来换成 Mann-Whitney U 只改本阶段）
  ↓
阶段4：构建数值矩阵（样本×特征）→ half-min 填补 → 归一化 → log₂(x+1) → fold change 暂留筛选 → Pareto scaling → 转换输出格式
```

各阶段职责边界：

- **阶段2 只做分组**：把分散的峰归并为 consensus peak，不决定去留
- **阶段3 只做过滤**：根据统计准则决定哪些特征进入矩阵；未来替换统计方法只改本阶段
- **阶段4 全程使用数值矩阵**（样本×特征 的纯数值 DataFrame），最后再拼 class 列转成输出格式，避免 class 行混入数值操作

### v1.15.5 — 修复阶段2峰对齐边界效应 + 归一化卡死（2026-04-26）

**问题1：固定 bin 边界效应**

原阶段2使用固定 bin：

```python
all_peaks_df['mz_group'] = np.round(all_peaks_df['mz'] / 0.2) * 0.2
```

bin 边界固定在 0.0、0.2、0.4 … 的整倍数处。两个只差 0.07 Da 的峰若跨越边界则被分入不同 bin，输出中出现本应合并的相邻特征（如 907.66 和 907.73）。

**修复**：改用贪心聚类 `_greedy_mz_grouping`——对 m/z 升序扫描，当前峰与**当前组起始峰**差 > 0.2 Da 才开新组，否则归入当前组。组内最大跨度严格 ≤ 0.2 Da，不存在链式漂移（漂移只在与"上一个峰"比较时才出现）。对一维排序数据，此方案等价于完全链接（complete-linkage）层次聚类，时间复杂度 O(n)。

---

**问题2：归一化阶段 GUI 卡死**

归一化使用逐行 `.loc` 就地赋值：

```python
for file_id in matrix.index:
    matrix.loc[file_id, :] /= norm_factor
```

pandas 2.0+ 启用了 Copy-on-Write（CoW）机制，每次 `.loc` 就地操作都会触发完整 DataFrame 复制。样本数 × 特征数越大，每轮复制开销越高，加之 Tkinter 单线程在此期间没有 `root.update()` 机会，最终表现为 GUI 卡死。

**修复**：收集所有样本的归一化因子后，用 `DataFrame.div(Series, axis=0)` 一次广播完成：

```python
norm_factors = {file_id: factor, ...}
matrix = matrix.div(pd.Series(norm_factors), axis=0)
```

pandas 内部用 numpy 广播处理，N 次 CoW 复制变为 1 次矩阵运算，GUI 不再冻结。

**改动清单**：

| 文件                     | 位置                        | 改动                                                  |
| ---------------------- | ------------------------- | --------------------------------------------------- |
| `data_preprocessor.py` | `_phase2_consensus_peaks` | 固定 bin 替换为 `_greedy_mz_grouping` 调用                 |
| `data_preprocessor.py` | 新增 `_greedy_mz_grouping`  | 贪心聚类：m/z 升序扫描，与组起始峰差 > tolerance 才开新组               |
| `data_preprocessor.py` | `_phase3_build_matrix`    | 归一化由逐行 `.loc /=` 改为 `DataFrame.div(Series, axis=0)` |

### v1.15.9 — 修复 BH-FDR 在小样本场景下全军覆没（2026-05-08）

**问题描述**

第二批数据（`第二批/HC`、`第二批/LC`，文件名含 `_merged`）在开启归一化时，特征筛选阶段返回空列表；关闭归一化则可正常得到约22个特征。第一批数据不受影响。

**排查过程**

1. **定位过滤瓶颈**：在 `_select_features_mannwhitney` 增加日志，发现日志输出为：
   ```
   特征筛选: 2076 → FC(1.3) → 1385 → MW-U(p<0.05) → 0 → 交集 → 0
   ```
   瓶颈在 MW-U 阶段，FC 不是问题。

2. **排查 FC 计算**：初步怀疑归一化后 FC 反变换公式失效（归一化→强度变小→log 值接近0→反变换后两组均趋近0→FC失真）。尝试改为 log 域差值 `2^|Δmean|`，但导致批次1也全部失效，随即回滚。

   复盘原因：原公式 `(2^a-1)/(2^b-1)` 在 b→0 时分母趋近 tiny，实际放大了 FC；改为 `2^|a-b|` 消除了这个放大，但对于 half-min 填补后一组均值本身很小的情况，FC 也随之跌破阈值，误伤批次1。

3. **验证真正瓶颈**：打印原始 p 值分布，批次2最小原始 p=0.0008，BH 校正后：
   ```
   q = 0.0008 × 2076 / 1 = 1.66 → 截断为 1.0
   ```
   全部 adjusted p = 1.0，无一通过 q < 0.05。

4. **排查特征数量能否压缩**：在阶段3增加出现率分布日志：
   ```
   ≥50%: 2076    ≥60%: 1649    ≥70%: 1381    ≥80%: 1138    ≥90%: 848
   ```
   即使要求90%出现率，仍有848个特征。BH 通过至少一个特征需 N < 63（0.0008×63≈0.05），提高 `MAX_MISSING_RATE` 无法解决问题。

**根本原因**

批次2文件经过合并处理（`_merged`），数据点密度约为批次1的5倍（81569 vs 15167），且强度几乎全部非零，导致峰候选数从批次1的 ~727 暴增至 2076。样本量不变（约52个），BH-FDR 的多重检验校正随特征数线性增大，小样本+大特征池时过于保守，在无强信号的批次中会全部过滤。

**标准 SOP 参考**

代谢组学小样本场景（样本数 < 100、特征数 > 500）下，BH-FDR 过于保守是已知问题。实际流程中常用原始 p 值配合特征数截断（`MAX_FEATURES`）作为替代。

**修复**

将 `FDR_CORRECTION` 改为 `False`，改用原始 p 值过滤，保留 `MAX_FEATURES = 50` 截断作为结果控制上限。

修复后批次2（带归一化）：
```
特征筛选: 2076 → FC(1.3) → 1385 → MW-U(p<0.05) → 23 → 交集 → 22
```

**改动清单**

| 文件        | 位置          | 改动                                                              |
| --------- | ----------- | --------------------------------------------------------------- |
| `config.py` | `FDR_CORRECTION` | `True` → `False`；注释说明小样本场景下 BH 过于保守，改用原始 p 值 + MAX_FEATURES 截断 |

**两批数据对比（修复后，归一化 max）**

| 批次 | 进入 MW-U | 通过 FC | 通过 MW-U | 最终特征数 |
|------|---------|--------|---------|--------|
| 第一批 | 727     | 554    | 548     | 50（截断）|
| 第二批 | 2076    | 1385   | 23      | 22     |

第二批最终特征数较少，与数据本身的 HC/LC 分离度较低有关（merged 处理平滑了峰形，降低了类间差异），属于数据质量问题，非流程问题。

**向后兼容性**

所有新 key 均通过 `loaded.get(key, 默认值)` 读取：旧格式 bundle（缺少新 key）加载后 `log_transform=False`、`scaling_method=None`，退化为仅做归一化的旧行为，不报错。

**注意事项**

此更新后，已有的旧 bundle 预测行为不变；需重新执行一次完整的【预处理 → 训练】流程才能生成包含完整参数的新 bundle，预测侧变换链方可正确生效。
