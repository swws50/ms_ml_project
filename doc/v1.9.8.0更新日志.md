# DETEQX v1.9.8 更新日志

## 📅 发布日期

2025.11.23

## 🎯 本版本重点

重构数据预处理归一化架构，实现样本级归一化并优化用户界面。

---

## ✨ 新增功能

### 1. 归一化架构重构

- **样本级归一化实现**：归一化从特征矩阵构建阶段移至峰发现阶段，每个样本使用自己的统计特征进行归一化
- **新增 `NormalizationManager` 类**：独立的归一化管理器，负责统计特征收集和归一化应用
- **支持的归一化方法**：
  - `sum`：总离子流(TIC)归一化
  - `median`：中位数归一化
  - `不归一化`：使用原始数据

### 2. 用户界面优化

- **归一化设置集成**：在数据分类窗口的"基础设置"区域新增归一化方法选择器
- **简化操作流程**：一个下拉菜单即可选择归一化方法，无需额外配置
- **文件命名优化**：输出文件根据归一化方法自动添加后缀（如 `processed_data_sum.csv`）

## 🔧 技术改进

### 1. 数据流程优化

**归一化执行时机**：

- **修改前**：峰发现 → 特征选择 → 构建矩阵时归一化
- **修改后**：峰发现 → 立即归一化 → 特征选择 → 构建矩阵

**优势**：

- ✅ 符合分析化学标准实践
- ✅ 每个样本独立归一化，消除技术变异
- ✅ 数据流程更清晰，易于理解和维护

### 2. 统计特征收集

在 `_discover_peaks_from_file` 方法中自动收集每个样本的统计特征：

```python
self.normalization_stats[file_id] = {
    'sum': results['intensity'].sum(),
    'median': results['intensity'].median()
}
```

### 3. 缓存更新机制

归一化后立即更新 `all_file_peaks_cache`，确保后续矩阵构建使用归一化数据：

```python
file_id = all_peaks_data[i]['file_id'].iloc[0]
self.all_file_peaks_cache[file_id] = all_peaks_data[i]
```

## 🐛 Bug 修复

### 1. **[严重] 修复保存原始数据的问题**

- **问题**：启用归一化后，保存的文件仍是原始数据
- **原因**：归一化后的数据未更新回 `all_file_peaks_cache`，矩阵构建时读取的是原始缓存
- **修复**：归一化循环中添加缓存更新逻辑

### 2. **[中等] 修复日志信息误导性**

- **问题**：显示"归一化因子范围"容易产生误解
- **修复**：根据归一化方法显示准确描述
  - sum 方法：显示"样本总离子流(TIC)范围"
  - median 方法：显示"样本中位数强度范围"

### 3. **[中等] 清理 data_store 残留调用**

- **问题**：代码中残留多处 `data_store.get_normalization_method()` 等调用
- **修复**：完全移除对 data_store 归一化相关方法的依赖，改用 DataPreprocessor 内部状态管理

## 📖 使用说明

### 归一化方法选择

1. 打开数据分类窗口
2. 在"基础设置"区域选择归一化方法：
   - **不归一化**：保留原始强度值，适用于已预处理数据
   - **sum (总和)**：TIC归一化，消除进样量差异，推荐用于代谢组学
   - **median (中位数)**：中位数归一化，对极端值更稳健

### 技术原理

每个样本独立归一化：

```
样本A归一化强度 = 原始强度 / 样本A的统计值（sum或median）
样本B归一化强度 = 原始强度 / 样本B的统计值（sum或median）
```

---

## ⚠️ 注意事项

1. **归一化不可逆**：归一化后的数据会覆盖缓存，如需原始数据请选择"不归一化"
2. **方法选择**：建议根据数据特征选择合适方法，不同方法会产生不同结果
3. **文件管理**：不同归一化方法的输出文件会分别保存，注意文件命名
