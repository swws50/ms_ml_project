## v1.12.1(2026-03-24）

### 新增：诊断报告导出时显示模型性能指标（`print_manager.py`、`model_predictor.py`）

#### 背景

此前"模型信息"段落仅输出模型类型与"训练状态: 已完成"，不包含任何量化指标，报告对生物医药背景读者的参考价值有限。

#### 实现

**`print_manager.py`——新增 `_load_metrics_summary(model_path)`**

根据模型路径（`models/*.joblib`）自动推导同名 metrics 文件路径（`metrics/*.json`），从中读取每折的混淆矩阵、AUC、F-score，用与 `visualization.py` 一致的 t 分布公式计算 95% CI，返回摘要 dict。

* 路径推导同时兼容正斜杠与反斜杠，兼容 `pathlib.WindowsPath` 对象（先 `str()` 转换再做字符串替换）
* 文件不存在或解析失败时静默返回 `None`，不影响报告其余内容

报告"模型信息"段落由原来 2 行扩充为：
    模型信息:
      模型类型: PLSRegression
      交叉验证: 5折×20次重复 (100次迭代) (Youden's J)
      AUC-ROC:        0.984 ± 0.006  [95% CI: 0.978 ~ 0.990]
      灵敏度 [HCC]:    0.935 ± 0.018  [95% CI: 0.917 ~ 0.953]
      特异度 [Normal]: 0.970 ± 0.012  [95% CI: 0.958 ~ 0.982]
      F1 Score:       0.952 ± 0.010

类别标签直接取自 metrics JSON 的 `meta.class_names`，与训练时状态保持一致。

**`model_predictor.py`——`_apply_loaded` 同步 `model_path` 到 `data_store`**

原本只有 `model_training.py` 在训练完成后调用 `data_store.set_latest_trained_model`；通过文件选择器或目录扫描加载已有模型时，`model_path` 不写入 `data_store`，导致 `get_latest_model_info()` 返回 `has_model=False`，模型信息段完全不显示。

`_apply_loaded` 新增可选参数 `model_path: str = None`，有路径时自动同步到 `data_store`；`load_model` 的 case 1（用户手动选择）和 case 3（目录扫描）分别传入对应路径。

#### 同时修复

* **类别名称索引 bug**（`_generate_content`）：训练数据类别分布循环中，原代码用枚举变量 `i` 索引 `class_names`，改为用字典键 `int(cls)`，避免键顺序非 0/1 时名称错位。
* **删除永远不执行的分支**：数据集信息段"数据来源"行的三元表达式条件与外层 `if` 恒等（`total > 0` 蕴含 `class_0 > 0 or class_1 > 0`），`CSV文件导入` 分支永远不可达，直接删除该行。

## v1.12.2(2026-03-24)

### PDF 诊断报告重构（`print_manager.py`）

将原有基于 `canvas.drawString` 的纯文本 PDF 输出升级为 ReportLab Platypus 布局引擎，输出具有视觉层次和图表的临床格式报告。

---

#### 渲染引擎

|      | 改造前                 | 改造后                             |
| ---- | ------------------- | ------------------------------- |
| API  | `canvas.drawString` | `SimpleDocTemplate` + Flowables |
| 换页   | 硬编码 `y < 50`        | Platypus 自动处理                   |
| 字体层次 | 全部相同                | 节标题加粗大字号、正文普通                   |
| 数据呈现 | 纯文本                 | 文本段落 + 指标 `Table`               |
| 图表   | 无                   | `Image` 嵌入已有 PNG，并排排列           |
| 强制分页 | 无                   | `PageBreak`                     |

---

#### 页面结构

**情况 A：有病人信息（姓名 / 年龄 / 编号至少一个不为空）→ 两页**

- 第一页：病人基础信息、预测结果、模型基本信息
  - 模型基本信息包含：模型类型、AUC 均值、交叉验证方案
  - 勾选"训练信息"时，模型基本信息下追加：样本数、特征数、类别分布、数据平衡性
- 第二页：模型性能指标表（AUC / 灵敏度 / 特异度 / F1，含 ± 和 95% CI）、数据集信息、评估图表

**情况 B：无病人信息 → 单页**

- 模型性能指标表、数据集信息、评估图表

---

#### 样式规范

- 报告标题居中，字号 18，标题下方 2pt 深蓝粗横线（`HRFlowable`）
- 节标题字号 14，深蓝色，上间距 12pt
- 正文字号 10
- 指标表格撑满页宽，深色表头，细网格线，数字列右对齐
- 中文字体降级策略：SimSun → SimHei → Helvetica

---

#### 图表排布

ROC 曲线与混淆矩阵并排两列显示，各占页面可用宽度约 50%，高度限制 200，图下方附图注。

---

#### 打印流程简化

- 移除"导出到文本文件"勾选框，PDF 为唯一导出格式
- 移除 `reportlab` 未安装时的 `ImportError` 提示弹窗（打包为 exe 后库随包内置）
- `execute_print` 直接调用导出，不再条件判断

---

#### 对话框勾选项调整

- 新增"训练信息"勾选项，默认不勾；勾选后训练数据内容归入模型基本信息节下展示，不单独成节
- "数据集信息"默认不勾，"预测结果"和"模型信息"默认勾选

---

## v1.12.3（2026-03-24）

### PDF 诊断报告布局优化（`print_manager.py`）

#### 去除分页逻辑，统一为单页输出

原 v1.12.2 在有病人信息时强制插入 `PageBreak`，导致报告输出两页。经验证所有内容均可容纳在一页内，故移除该分支，任何情况下均输出单页。

- 删除 `PageBreak` 及其 import
- 标题始终渲染在页面顶部，不再依赖 `has_patient` 条件
- `topMargin` 由 50 → 20，标题贴近页面顶部

#### 合并模型信息节，废弃性能指标表

原"模型基本信息"与"模型性能指标"（`Table` 渲染）两节存在 AUC 重复展示的冗余。合并为单一"模型信息"节，以缩进纯文本行输出：

```
模型信息
  模型类型：PLSRegression
  交叉验证：5折×20次重复 (100次迭代) (Youden's J)
  AUC-ROC：0.982 ± 0.033  [95% CI: 0.976 ~ 0.989]
  灵敏度 [类别1]：0.926 ± 0.086  [95% CI: 0.909 ~ 0.943]
  特异度 [类别0]：0.968 ± 0.058  [95% CI: 0.957 ~ 0.980]
  F1 Score：0.946 ± 0.049
```

- 删除 `metrics_table()` 辅助函数
- 新增 `style_indent`（`leftIndent=20`）、`style_indent2`（`leftIndent=40`）两个段落样式

#### 训练数据信息独立成节

原"训练信息"内容附属于"模型基本信息"节下。现独立为"训练数据信息"节，由"训练信息"勾选项控制，包含样本数、特征数、类别分布及数据平衡性。

#### 内容缩进与间距收紧

- 病人基础信息、预测结果的各字段行改用 `style_indent`，与节标题形成视觉层次
- 节标题 `spaceBefore` 12 → 6，`spaceAfter` 4 → 2
- 横线 `spaceAfter` 10 → 6；各节末尾 `Spacer` 8 → 4
- 标题与横线之间的空白 `Paragraph` 改为 `Spacer(1, 12)`，精确控制间距
- 生成时间行改为右对齐

* * *

#### 已知 Bug（待修复）

**加载老模型时 PDF 图表错位**（`print_manager.py`）

加载非最新训练的老模型打印报告时，指标数值（AUC / 灵敏度等）来自该模型对应的 `metrics/{model}.json`，结果正确；但 ROC 曲线与混淆矩阵图表路径硬编码为 `get_output_paths()` → `charts/ConfusionMatrix.png` / `charts/ROC_Curve.png`，始终指向当前项目 `charts/` 目录下的最新图表，与实际加载的模型不符。

老模型的图表归档于 `charts/archive/{timestamp}/`，但目前没有任何机制将模型文件与对应的归档时间戳关联，导致无法反查正确图表。

**修复方向**：在训练完成时将图表路径（或归档时间戳）写入 `metrics/{model}.json`，`_export_to_pdf` 读取该字段后优先使用，回退到当前 `charts/` 目录。
