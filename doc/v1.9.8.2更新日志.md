# DETEQX 更新日志 v1.9.8.2

**发布日期**: 2025-11-26  
**类型**: 架构重构 / 代码清理 / Bug修复

---

## 概述

本版本完成了归一化逻辑的架构重构，将归一化功能完全封装到 `data_preprocessor.py` 中，清理了分散在多个模块中的历史遗留代码，并修复了预测时归一化方法不一致的严重Bug。

---

## 问题背景

### 历史遗留问题

原有架构中，归一化状态通过 `data_store` 模块全局管理：

```python
# 旧架构（已废弃）
data_store.set_normalization_enabled(True)
data_store.is_normalization_enabled()
data_store.get_normalization_factor()
```

这种设计存在以下问题：

1. **状态分散**：归一化开关在菜单、预处理、预测多处都有控制
2. **职责不清**：`data_store` 承担了不属于它的归一化逻辑
3. **预测时不一致**：预测新样本时无法得知训练数据使用了哪种归一化方法

### 预测归一化Bug

**严重程度**: 🔴 高

预测流程存在归一化不一致问题：

| 阶段  | 预期行为                      | 实际行为（Bug） |
| --- | ------------------------- | --------- |
| 预处理 | 用户选择max归一化，生成data_max.csv | ✅ 正确      |
| 训练  | 读取归一化后的特征矩阵训练模型           | ✅ 正确      |
| 预测  | 对新样本应用相同的max归一化           | ❌ 使用原始强度值 |

这导致预测时特征值与训练时不在同一尺度，影响模型预测准确性。

---

## 解决方案

### 1. 归一化方法从文件名推断

采用文件名约定方案，预测时从训练数据文件名自动推断归一化方法：

| 文件名               | 推断的归一化方法       |
| ----------------- | -------------- |
| `data_max.csv`    | max（除以最大峰）     |
| `data_sum.csv`    | sum（TIC归一化）    |
| `data_median.csv` | median（中位数归一化） |
| `data_raw.csv`    | 无归一化           |

### 2. 预测时自动应用归一化

`feature_detector.py` 重构后的预测流程：

```
读取训练数据路径
    ↓
从文件名提取归一化方法 (max/sum/median/none)
    ↓
读取预测样本原始数据
    ↓
计算样本统计值 {max, sum, median}
    ↓
提取特征时应用对应归一化
    ↓
返回归一化后的特征向量
```

### `feature_detector.py` 重构详情

**类属性变更**：

```python
# 旧
self.normalization_factor = None  # 归一化因子数值

# 新
self.normalization_method = None  # 归一化方法名 ('max'/'sum'/'median'/None)
```

**新增方法逻辑**：

```python
def _detect_normalization_factor(self, df):
    """从文件名推断归一化方法"""
    basename = os.path.basename(self.training_data_path)

    if '_max' in basename:
        return 'max', None
    elif '_sum' in basename:
        return 'sum', None
    elif '_median' in basename:
        return 'median', None
    elif '_raw' in basename:
        return None, None
    else:
        return None, None
```

**`process_prediction_sample` 核心变更**：

```python
# 计算预测样本的统计值
intensities = raw_data.iloc[:, 1]
sample_stats = {
    'max': intensities.max(),
    'sum': intensities.sum(),
    'median': intensities.median()
}

# 提取特征时应用归一化
for target_mz in training_mz_values:
    intensity = self._extract_intensity_for_mz(
        raw_data, target_mz, norm_method, sample_stats
    )
```

**`_extract_intensity_for_mz` 归一化应用**：

```python
if norm_method and sample_stats:
    norm_factor = sample_stats.get(norm_method)
    if norm_factor and norm_factor > 0:
        return max_intensity / norm_factor
return max_intensity
```

## 文件命名规范

### 数据文件

```
data_{normalization_method}.csv

示例：
- data_max.csv      # max归一化
- data_sum.csv      # TIC归一化  
- data_median.csv   # 中位数归一化

```

## 数据流对比

### 旧架构（已废弃）

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  菜单开关   │────▶│ data_store  │◀────│   预测时    │
│ 控制归一化  │     │ 全局状态    │     │  读取状态   │
└─────────────┘     └─────────────┘     └─────────────┘
                          │
                          ▼
                    ┌─────────────┐
                    │ 预处理/训练 │
                    │  读取状态   │
                    └─────────────┘
```

**问题**：状态可能在任意时刻被修改，预测时状态可能与训练时不一致。

### 新架构

```
┌─────────────────┐
│ data_preprocessor│
│  用户选择方法    │
│  生成data_xxx.csv│
└────────┬────────┘
         │
         ▼ 文件名包含方法信息
┌─────────────────┐
│  model_training │
│  读取并训练     │
└────────┬────────┘
         │
         ▼ 文件名保持不变
┌─────────────────┐
│ feature_detector│
│ 从文件名推断方法 │
│ 对新样本应用归一化│
└─────────────────┘
```

**优势**：归一化方法与数据文件绑定，不可能出现不一致。

## 验证要点

1. **预处理验证**：选择不同归一化方法，确认生成对应文件名
2. **训练验证**：确认模型文件名不再包含归一化状态
3. **预测验证**：
   - 使用 `data_max.csv` 训练后，预测新样本时日志应显示"检测到归一化方法: max"
   - 预测结果应与训练时使用相同归一化的结果一致
4. **回归验证**：确认删除的UI元素不影响其他功能

---

## 已知限制

1. **文件名依赖**：如果用户手动重命名数据文件，归一化方法推断将失败
2. **向后兼容**：旧版本生成的 `normalized_ms_data.csv` 或 `raw_ms_data.csv` 无法自动识别归一化方法

---

## 迁移指南

如需使用旧数据文件，请手动重命名：

```bash
# TIC归一化的数据
mv normalized_ms_data.csv data_sum.csv

# 未归一化的数据  
mv raw_ms_data.csv data_raw.csv
```
