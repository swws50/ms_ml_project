v1.9.12.7 (2026-03-07)
----------------------

### 状态栏重构：ProgressComponent 集成 3 个状态 Chip

#### 背景

原主界面 row=1 的**步骤向导条**（`HelpSystem.create_progress_indicator()`）不提供进行中／完成／失败的结果反馈；row=3 的全局进度条 `ProgressComponent` 运行时显示、结束后隐藏；`PreprocessingPanel` 内还存在一个从不被更新的孤儿 `status_label`（row=2）。整体引导不清晰，本次统一重构。

#### 新布局

    row=1（chip 容器，始终可见）
      [ 预处理: 等待开始 ]   [ 训练: 未训练 ]   [ 预测: -- ]
    
    row=2  ── 1px 分割线 ──
    
    row=3（进度条容器，仅运行时显示）
      步骤消息文字
      ████████████ 进度条

各状态 chip 图标：

| 图标  | 含义         |
| --- | ---------- |
| `○` | 等待开始 / 未训练 |
| `◐` | 进行中…       |
| `✓` | 完成 / 模型已加载 |
| `✗` | 失败         |
| `◼` | 已终止        |

各操作节点的 chip 更新逻辑：

| 操作       | 开始          | 成功         | 终止 / 取消   | 异常                |
| -------- | ----------- | ---------- | --------- | ----------------- |
| 预处理      | `进行中...`（蓝） | `完成`（绿）    | `等待开始`（灰） | `失败`（红）+ re-raise |
| 训练       | `进行中...`（蓝） | `完成`（绿）    | `已终止`（橙）  | `失败`（红）+ re-raise |
| 预测模型文件选择 | —           | `模型已加载`（绿） | —         | —                 |
| 预测执行     | 不更新         | 不更新        | 不更新       | 不更新               |

> 预测 chip 仅在用户选择模型文件时更新（`PredictionPanel._on_model_file_select` 回调），不监测预测结果。

### 修复状态栏 Chip 时机错误

**问题 1：按下预处理按钮后 chip 显示「等待开始」而非「进行中」**

根因：`show_classification_dialog()` 调用 `_create_classification_window()` 后立即返回（无 `wait_window`），导致后续逻辑将 chip 从「进行中」覆写回「等待开始」。

修复（`data_preprocessor.py`）：在 `show_classification_dialog` 末尾加 `wait_window`，使调用方阻塞至窗口关闭。`wait_window` 内部运行嵌套 Tcl 事件循环，UI 不卡死。

**问题 2：预处理完成后 chip 仍显示「等待开始」而非「完成」**

根因：`main.py` 用 `data_store.has_training_data()` 判断预处理是否成功，但 `data_preprocessor.py` 从未调用 `data_store.set_training_data()`，因此永远返回 False。

修复（`data_preprocessor.py` + `main.py`）：

* `DataPreprocessor` 新增 `self.preprocessing_completed = False` 标志
* `_save_and_notify_results` 保存成功时置 `True`
* `show_classification_dialog` 每次调用时重置为 `False`
* `main.py._handle_preprocessing_start` 改为检查 `self.data_preprocessor.preprocessing_completed`

### 代码清理：移除冗余设计

**`ui_components.py`**

* 删除 `ProgressComponent.__init__` 的 `show_label` 参数及 `self.show_label` 属性；`status_label` 无条件创建
* `chip_predict` 从 column=3 修正到 column=2，`grid_columnconfigure` 去掉多余的空洞列

**`help_system.py`**

* 删除内容为纯 `pass` 的 `update_progress_display()` 方法
* 删除 `advance_step()` 内对 `update_progress_display()` 的调用

**`model_predictor.py`**

* 删除 `self.help_system.complete_step("predict_sample")` 调用（`complete_step` 已在 v1.9.12.7 删除，此残留调用会导致运行时 `AttributeError`）

**`main.py`**

* 构造 `ProgressComponent` 时去掉 `show_label=True`

v1.9.12.7.2 (2026-03-07)
------------------------

### 修复自动化工作流与状态栏的冲突

**背景**：v1.9.12.7.1 在 `show_classification_dialog` 末尾加入 `wait_window` 后，`automated_workflow.py` 的轮询监控 `_monitor_preprocessing_completion` 出现计时错误：`start_time` 在对话框关闭后才被记录，导致 `os.path.getmtime(csv_path) > start_time` 条件始终为 False，训练步骤永远无法触发。此外，自动化流程绕过了 `_handle_preprocessing_start`，chip 在整个过程中始终停在默认灰色。

**方案**：引入回调机制替代轮询。在 `DataPreprocessor` 引入 `on_complete_callback`，预处理成功保存结果时主动触发；手动流程和自动化流程统一走回调。自动化流程执行期间三个 chip 统一显示 `⚙ 自动化中...`，结束后恢复各自最终状态。

#### `data_preprocessor.py` 变更

* `__init__` 新增 `self.on_complete_callback = None`
* `_save_and_notify_results` 保存成功后触发 `self.root.after(0, self.on_complete_callback)`（`root.after(0, ...)` 在 `wait_window` 的嵌套事件循环中安全调度，UI 不冻结）

#### `main.py` 变更

* `_handle_preprocessing_start`：调用 `show_classification_dialog` 前注册 lambda 回调（成功时更新 chip 为绿色 ✓），窗口关闭后在 `finally` 里清理回调；改为仅在未完成时重置灰色

#### `automated_workflow.py` 变更

* 删除 `_monitor_preprocessing_completion`（轮询逻辑完全移除）
* `_preprocessing_step`：设三个 chip 为 `⚙ 自动化中...`，注册 `_on_preprocess_done` 回调，窗口关闭后清理回调
* 新增 `_on_preprocess_done`：回调触发后 `root.after(1000, _training_step)`
* `_training_step`：移除废弃的 `_detected_csv_path` 引用，直接调用 `_find_latest_data_csv()`
* `_prediction_preparation_step` 成功结尾：恢复三个 chip 最终状态（预处理/训练绿色 ✓，预测绿色 ✓）；失败分支：预处理绿、训练红 ✗、预测灰 ○

待处理 Bug
-------

### 预测报「无法检测训练特征」

**现象**：在某些工作流下执行预测，结果面板显示「预测失败: 无法检测训练特征」。

**错误路径**：
    model_predictor.py → predict_file()
      → feature_detector.load_training_features()   # 返回 None
      → {"success": False, "error": "无法检测训练特征"}

**根本原因**：模型保存时只保存了 sklearn 模型对象本身，未保存训练特征的 m/z 列表。
    # model_training.py 中
    dump(self.best_model, model_path)   # 只保存模型，无特征元数据

预测时，`load_training_features` 需读取训练 CSV 才能得到 m/z 特征列表用于特征对齐。若当前会话未通过「选择 CSV 文件」加载训练数据（`data_store._training_data_path` 为 `None`），且输出目录下的 `data.csv` 不存在，则 `load_training_features` 返回 `None`，预测失败。

`data_store.set_training_data_path()` 只在两处被赋值：①用户点击「选择 CSV 文件」；② `automated_workflow.py`。`DataPreprocessor` 预处理完成后不调用该方法，因此仅做预处理不会填充该路径。此 bug 此前因用户总在同一会话内按顺序完成「预处理→选CSV→训练→预测」而未触发。

**修复方案**：在 `save_training_results()` 保存模型时，将训练特征列表和归一化方法一并打包存入同一 `.joblib` 文件：
    # model_training.py save_training_results() 中
    model_bundle = {
        "model": self.best_model,
        "training_features": <从 data_store 或 DataFrame 中取得的 m/z 列表>,
        "normalization_method": <从文件名或 config 取得>
    }
    dump(model_bundle, model_path)

在 `model_predictor.py load_model()` 中检测是否为 bundle 格式，并保持对旧格式 `.joblib` 的向后兼容：
    loaded = load(model_path)
    if isinstance(loaded, dict) and "model" in loaded:
        self.model = loaded["model"]
        self.feature_detector.training_features = loaded.get("training_features")
        self.feature_detector.normalization_method = loaded.get("normalization_method")
    else:
        self.model = loaded   # 兼容旧格式

这样预测时完全不依赖训练 CSV 是否存在，消除 `load_training_features` 读文件失败的可能。
