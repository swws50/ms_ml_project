# v1.8 更新日志

**更新日期**: 2025年8月25日  
**版本**: v1.8.0 模块化重构版

## 🏗️ 核心架构变化

### 从单体到模块化

- **之前**: 一个巨大的 `model_training.py` (1200+行)
- **现在**: 拆分为专门的模块，职责明确

### 新架构图

```
split_version/
├── main.py (程序入口 + UI协调器)
│   └── MainGUIManager (主界面管理器)
│       ├── TrainingUI (训练逻辑)
│       ├── PredictionManager (预测+模型信息)
│       └── UI Components (5个界面组件)
├── 核心业务模块
│   ├── data_processing.py (数据预处理)
│   ├── model_training.py (模型训练)
│   ├── model_predictor.py (样本预测)
│   └── feature_detector.py (特征检测)
├── 支撑系统
│   ├── config.py (配置管理)
│   ├── data_store.py (数据存储)
│   ├── utils.py (工具函数)
│   └── help_system.py (帮助系统)
├── 辅助模块
│   ├── ui_components.py (UI组件库)
│   ├── validation_decorators.py (验证装饰器)
│   ├── visualization.py (图表生成)
│   └── output_manager.py (文件管理)
└── __init__.py (包标识)
```

## ✨ 新增功能

### UI组件模块化

- 5个独立Panel类: Control, Result, Prediction, Visualization, Info
- BasePanel基础类提供通用功能
- 回调机制处理组件间通信

### 统一管理器

- **PredictionManager**: 合并了预测和模型信息功能
- **TrainingUI**: 专门处理训练界面逻辑
- **MainGUIManager**: 总协调者，管理所有UI和业务逻辑

### 数据存储路径

- **data_store.py**: 全局数据仓库
- 统一的数据存取接口
- 所有运行时产生的文件都有专门的保存路径

## 🔧 重大修复

### 硬编码路径Bug

- **问题**: 训练和预测使用不同的文件路径
- **解决**: 自动保存用户选择的训练文件路径
- **效果**: 预测时能正确找到对应的特征文件

### 类别映射统一化

- 删除冗余的 `get_current_class_names()`, `get_class_mapping_for_labels()`, `update_class_names()`
- 统一为 `get_class_mapping(labels=None)` 一个函数
- 支持动态类别名称，不再限制HC/LC

### 向后兼容清理

- 删除 `feature_detector.py` 底部的便捷函数
- 移除未使用的备用策略参数

## 🔄 程序构建方式

### 数据流转

```
用户操作 → UI组件回调 → MainGUIManager → 业务逻辑Manager → data_store → 文件保存
```

### 设计模式

- **中介者模式**: MainGUIManager协调各组件
- **观察者模式**: 回调机制处理用户交互  
- **外观模式**: Manager类封装复杂业务逻辑
- **单例模式**: data_store全局数据存储

### 包管理

- 添加 `__init__.py` 使项目成为标准Python包
- 简化外部导入: `from split_version import create_gui`
- 利好PyInstaller打包成exe

## ⚠️ 已知问题

### 可视化面板重置

- 因为初期设计缺陷，重置时需要重新创建整个面板；临时方案：为销毁旧面板，创建新面板；根本原因：缺少"容器稳定，内容可变"的设计
- 由于归一化因子是在数据预处理步骤自动保存，若是用户从外部直接导入一个.csv，程序找不到对应的归一化因子会报错

### 技术债务

- 部分UI组件没有完善的清理方法
- 可视化显示采用"替换"而非"更新"模式
